# Research execution workflows

The 100-step programme and completion ledger are in `docs/research/`. Results and private observer work files live under `/workspace/braink-setup/research-100`; credentials remain in owner runtime state outside Git.

`baseline.py` verifies the current nine repositories, qualified source, fourteen custody sources, live family health, advancing bilateral cycles, authority rejection, package-cache hashes, governance and actual dependency versions. It observes rather than assumes prior runtime readiness. Use `--output /workspace/braink-setup/research-iteration-UNIQUE` for another run; existing completed evidence is not overwritten. Its 60-second HTTP deadline is bounded and recorded; it does not change the admitted engine's transport configuration.

`vfs_experiments.py` retrieves the exact pre-fix VFS source from the private repository commit recorded in the script. It runs synthetic capacity, cursor, historical-tamper and concurrent-writer experiments in temporary stores; the live VFS database is not modified. Primary-source fingerprints must exist in the research evidence directory. Timing includes instrumentation and concurrent cloud load.

`qualify_vfs_deployment.py` checks the actual managed VFS process, selected source fingerprint, event route and all nine retained subscriptions after deployment. It does not promote new packages.

`apply_steps.py --start 1 --end 20` admits completed step JSON artifacts to owner VFS, separately reads bytes and obtains observer receipts, executes digest-bound R36 transactions through the owner gateway, invokes the supplied detached journal verifier, validates signatures/transaction identities and waits for all nine family caches. A step is marked completed only after that chain agrees. Repeat application of unchanged completed inputs returns without duplicate execution. Changed completed inputs require a new versioned iteration instead of rewriting evidence.

These workflows require the exact admitted owner packages, running controllers, configured private authority files and the qualified engine interpreter. Run them with the canonical `.venv/bin/python`. Source research, local execution/readback and independent external assessment are distinct. Original raw owner inputs and private signing keys are never included in public research reports.

`apply_domain_capacity.py --memory-mib 256` reports a dry run for existing domains whose owner-root labels match the nine admitted families. Add `--apply` to perform the bounded operational override; it preserves mounts and records actual before/after configuration. It does not change the new-domain factory default or establish sustained capacity qualification.
