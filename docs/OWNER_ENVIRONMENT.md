# Owner-governed WEB4 server environment

The cloud server launch uses the owner's ten source packages and selected executable K-Cloud notebook components. `owner_kernel.py` retains the actual `SovereignHardgate`, `ZeroLessIndexEngine`, `DynamicHealingAgent`, `KCloudNode` and `StochasticKuramotoPLL` class bodies from the two owner Python uploads. Source hashes and private custody paths are in OWNER_SOURCE_MANIFEST.json. Notebook shell/install cells and demonstration startup loops are not imported.

Every authenticated gateway control routes through the owner KCloudNode zeroless boundary. The original hardgate's A.KEDDEH string check is retained as an owner routing contract alongside gateway token authentication; it does not replace cryptographic authentication. Workstation execution, R36 commits, network MCP, estate MCP, broker/agent boot, periodic observer, workbook diagnostics and signed namespace state use the supplied package implementations. The cloud adapter provides Linux lifecycle and transport bindings.

Bilateral execution remains enabled across controller restarts. Every five seconds it reads real workstation health/telemetry, advances the owner's software PLL, incorporates bilateral healing and the preceding R36 return, persists a complete intent, and commits ten directional mapped registers through the original R36 worker. Each returned prefix is persisted before the next register. Partial cycles resume with the same tenant/node/nonce rather than discarding state. Failed feedback pauses side effects and preserves the pending prefix for recovery. Registers are software actuators. The oscillator variables are software governor state, not measurements of electrical power or physical resonance. No fabricated stochastic jitter is injected in the deployed PLL. The namespace signs completed cycle evidence; a crash after signing but before final state publication can produce another valid cycle receipt on retry.

The persistent domain mesh implements the owner's dual-homed correction. Each new domain owns a new internal Docker bridge/network namespace, joins its parent's downstream bridge as its upstream anchor, and runs three separate processes executing the exact supplied workstation source on local ports 19100–19102. These repeated ports reside in separate namespaces. The domain bridge exchanges real runtime telemetry and software phase/epoch state with its parent; a translated deterministic form of the supplied wrapped Kuramoto equations drives phase capture. Immutable owner code is mounted read-only and mutable phase/epoch state is outside it. The carrier image is pinned by digest; per-domain memory/CPU/process limits and a maximum of eight domains define this cloud instance's configured capacity.

Each domain retains its own state and downstream network when its anchor is lost. It enters flywheel, continues its local workstation runtime, and can reanchor to an ancestor without resetting the phase/epoch. Cyclic parent assignments are rejected. Docker restart policy rehydrates a domain from its retained state if its bridge or workstation exits. The host supervisor resumes its admitted mesh and recovers all owned subprocess service roles with a bounded restart rate. These domains share one physical cloud host; WAN/BGP/Anycast placement is a separate infrastructure binding. The platform's cloud agent and host OS remain the execution vessel; no replacement of the platform operating system has been performed.

`bash scripts/start_web4_cloud.sh` starts the owner server, resumes existing domains and admits a three-domain genesis chain on first activation. `bootstrap_owner_environment.py` activates bilateral execution only on first admission, preserving a later explicit operator pause. Terminal commands include `cloud bilateral start|pause|status`, `cloud domains` and `cloud hci`; all three preserved HTML carriers also expose these controls. The Shared KEDDEH HCI adapter binds headers, state and evidence traces to actual readbacks. Uploaded mock watchdog, certified-slot, MRAM and quorum strings are not presented as measured facts. Physical A/B partitions, hardware watchdog and FROST signatures require their actual hardware/key bindings; this cloud directory layout is not a flashed SD card or independently certified ISO implementation.

Validation includes an actual intermediate-domain outage: genesis and the descendant remain alive, the descendant's epoch advances in flywheel, and it reanchors while retaining its own downstream network. Run `scripts/verify_owner_domains.py --output /outside/checkout/domain-evidence.json` against the admitted local test runtime; this temporarily stops its intermediate domain and restores the original chain afterward. The full candidate qualification runs installed-wheel tests plus live package/browser/domain checks. The private library retains original owner files; the public source includes selected operational derivatives and custody hashes.
