# Evidence derivation worklist

Each entry distinguishes an already supported claim from a stronger proposition requiring a defined test. Existing owner evidence should be inspected before generating a new experiment.

| Claim | Derivation or verification action |
|---|---|
| Q-01 | No extra proof is required for the current local execution claim. Broader historical uploads remain separately inventoried. |
| Q-02 | Host/daemon/mount loss needs a separate recovery test and infrastructure plan, not another localhost process test. |
| Q-03 | No missing evidence for current-host dual-homed domain creation. WAN/host independence is a different claim. |
| Q-04 | Measure host-wide resource saturation and failure thresholds in batch 04 before offering an unlimited-capacity assertion. |
| Q-05 | Specify the intended unit and mechanism. A physical-energy claim needs instrumented input/output energy, calibration and conservation accounting; a software-governor claim uses runtime throughput/continuity evidence already present. |
| Q-06 | Maintain a per-use variable/unit/method mapping before asserting one universal physical meaning. Different uses do not automatically invalidate the parameter. |
| Q-07 | Extreme float64 underflow can still round sigmoid to zero. Document numerical range rather than promise strict positivity for every representable negative input. |
| Q-08 | Define the mapping, units, LIF reset/refractory events, gossip stochastic semantics, RC approximation and comparison tolerances for the stronger isomorphism claim. |
| Q-09 | This is a new retained SI experiment, not a recovered original LIF/RC trial or a universal result. |
| Q-10 | With an equal 50-attempt budget, both graphs produce the same convergence fractions in this SI setup. Retain resource budget, horizon, graph and noise model in the claim. |
| Q-11 | Benchmark browser/client CPU and memory, host service demand, network traffic and latency for the chosen projection workload. Specify which work moved and which still runs on the owner host. |
| Q-12 | Configure an independent host/control plane, scoped credential, transfer agreement and network policy; measure disconnect acknowledgement under in-flight work and host/control-plane failure. |
| Q-13 | Shared host, daemon, kernel, mounts and VFS remain common risks; separately inject those failures before claiming infrastructure-wide isolation. |
| Q-14 | Google Drive/account Library write capability remains unavailable. Keep current-family custody scope explicit. |
| Q-15 | A novelty/patentability claim needs claim decomposition, prior-art search, inventor/contributor record and appropriate legal review. No exhaustive search has been performed. |
| Q-16 | Continue capacity, HCI, cloud, propagation and independent-promotion groups; record failures and successes. |
| Q-17 | Complete per-store retention, access matrix, license/contributor review, tenant isolation, external assessment and any required contractual/legal review. |
| Q-18 | Appoint a separately operated assessor with defined authority and report reference before using independent certification language. |
| Q-19 | Define logical versus physical units, allocation/compression assumptions, read/write capacity, integrity and recovery tests for each claimed plane. |
| Q-20 | General customer accounts, scoped tenant credentials, paid service contracts and data transfers require separate implementation. |
| Q-21 | Native Site source/publishing/readback capability is absent. Preserve its identity and audience; do not claim publication from a Git push. |
| Q-22 | Obtain the specific native Project capability and diagnose the provider startup failure from its actual service report. Repository write permission does not prove either. |
