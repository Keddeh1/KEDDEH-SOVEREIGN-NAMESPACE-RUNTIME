1. Purpose and scope

Build a reusable media branch of the existing BRAINK console for original videos, shorts, long-form releases, podcasts, narration, screen capture and reusable visual assets. The goal is repeatable native processing and coherent owner controls, with provider observations determining external success. Research spans 23 components and service areas. This is a scoped market study, not a claim to have evaluated every product or benchmarked commercial competitors.

2. Requirements and evaluation method

Evaluate each candidate for replicability, code availability, licensing, headless execution, local processing, editorial control, capture support and integration cost. Primary project/provider pages were inspected. Direct network retrieval failed for some domains; the connected web tool recovered most primary pages. Evidence records both methods and failures. No vendor engagement claim, unobserved performance result, fabricated price or licence approval is accepted as measured evidence.

Separate four categories: installed execution engines; human desktop editors; source-available/licence-restricted frameworks; commercial workflow comparators. A user-friendly workflow must preserve originals, explain queued versus completed status, show errors, expose keyboard controls and accommodate reduced motion.

FFmpeg is the strongest immediate native execution foundation because one process supports decoding, resizing, cropping, loudness mastering, encoding, still extraction and animation. PySceneDetect adds observable scene boundaries. faster-whisper provides an offline-capable transcription engine once a compatible model is provisioned. Shotcut and Kdenlive are strong human-review companions; they do not become unattended services merely because they are installed. OBS complements browser capture for a future native desktop integration.

Commercial comparators concentrate on three workflows: OpusClip on repurposing to clips, Descript on transcript-oriented editing and speech workflows, Riverside on recording and repurposing. Their hosted services cannot be replicated by copying a frontend. This branch implements narrower observable primitives and leaves semantic selection, polished neural voices and advanced composition as separate work.

4. Technical architecture and implemented functions

The existing BRAINK cloud dispatcher records execution requests and results through its translation-ledger capability. That receipt does not establish that a YouTube action succeeded. D1 stores library documents, scripts, edit revisions, upload state and jobs. R2 stores source and derived bytes. The owner website proxy routes requests to the runtime. A Node worker claims jobs atomically, downloads actual source bytes, runs Python and FFmpeg, probes output files, uploads them and records observations.

The cinematic console includes source upload, search and filters; playback and trim controls; saved edit revisions; browser rendering; narration and on-screen scripts; permission-based screen recording; frozen frames with brightness and caption edits; PNG library assets; portrait short, long-form and mastered podcast profiles; synthetic English speech; frame zoom animation; reviewed YouTube release controls and observed job activity. Browser capture requires explicit source selection and supported codecs. Transcription is not presented as available while model provisioning is blocked.

The Node SDK separates routes and query parameters, rejects remote cleartext endpoints, limits request time and propagates provider errors. The official MCP SDK exposes owner-scoped status, library, scripts, processing and cancellation. Public posting remains in the reviewed release flow. Docker Compose and systemd definitions support conventional deployment; they have not yet been installed or qualified as permanent services.

5. Results and execution evidence

The existing frontage suite passed 116 tests. Four SDK/MCP checks passed, including an actual stdio MCP handshake and tool enumeration. Chromium verified uploading a generated media fixture, saving an edit, saving a real decoded frame, saving narration, rendering an export and persistence after reload. The 375-pixel surface had no horizontal overflow and reduced-motion state was exercised. These tests used real SQLite/filesystem fixture storage and did not substitute for production BRAINK or YouTube readback.

Native FFmpeg processing produced a 5.00-second portrait clip (597,928 bytes), a 6.00-second long-form export (2,684,582 bytes), a 5.952-second podcast (143,571 bytes), a 3.88-second Flite voice-over (124,238 bytes) and a 2.00-second animation (30,099 bytes). Duration and file sizes were probed from actual outputs. The source was a generated test pattern with a sine tone; no customer editorial quality, scale performance or audience outcome was measured.

6. Economics, licensing and deployment options

For self-hosting, estimate monthly cost as compute hours times measured compute rate, plus retained source/export GB times storage rate, plus transfer and request costs, plus backup retention and operator time. For hosted competitors, evaluate subscription, seats, included processing/transcription minutes, additional credits, export limits, storage, language support and workflow lock-in. Primary-domain search extraction showed OpusClip Starter $15/month and Pro $29/month, and Riverside Pro $29/month, Grow $39/month and Webinar $99/month. Riverside showed lower annual equivalents. These displayed amounts are not checkout quotes: currency, tax, region, credits and commitment need verification. Descript amounts were not reliably extracted. Obtain dated vendor quotes before procurement. Zero licence fee does not imply zero operating cost.

The local FFmpeg build enables GPL components including x264; its exact build configuration is recorded. Docker's Debian build may differ and must be checked before distribution. Code licences and downloaded voice/model licences must be tracked separately. Remotion and n8n need licence-specific commercial-use assessment rather than an unrestricted open-source label. No upstream binaries or speech models are redistributed in this package.

Recommended execution split: browser control/capture plus the existing authenticated cloud runtime for records and storage, with a dedicated Linux Node/Python worker for substantial native media processing. HTML/VFS alone does not grant a browser native process or arbitrary TCP privileges. Reusable Node modules, explicit process arguments and owner-scoped APIs provide the conventional deployment boundary.

7. Limitations, risks and unresolved work

The media changes are not yet production-deployed. Google OAuth client configuration, account consent and a verified channel are absent. No live YouTube action has been tested. Speech-model download returned HTTP 403. Complex multi-track editing, semantic ranking, automatic script generation, native text overlays and YouTube caption upload are incomplete. Comment review retrieves provider data and creates generic labelled drafts; it does not automatically post replies or establish customer rapport outcomes.

Worker failures are saved and expired leases are exposed for reconciliation. Ambiguous upload effects deliberately stop retries; the owner reconciliation tool and robust heartbeat/output-adoption lifecycle need completion. Interactive screen capture, long-recording memory pressure, container execution, large uploads and production rollback need further qualification. The complete unresolved list is machine-readable in unresolved.json.

8. Recommendation and DevOps acceptance gates

Keep this isolated as feature/braink-media-console in the existing canonical runtime repository. Submit an implementation draft and central DevOps intake task. Complete owner authentication and direct D1/R2/BRAINK readback in production, add provider reconciliation and worker recovery, provision licensed speech models, verify Google OAuth and a private YouTube upload, then obtain independent assessment and exercise rollback before readiness. Do not mark the candidate scheduled or deployed from local tests alone.
